# AGENTS.md

Guidance for agents working on the MiSTer menu core — upstream Menu_MiSTer plus
a PSX SNAC pad reader. `CLAUDE.md` is a symlink to this file.

Read `docs/state-todo.md` before starting. It is short, it is ranked, and every
item cites a file and line.

## What is ours and what is not

Almost none of this repository is ours. `sys/` is the MiSTer framework, taken
wholesale from upstream. `menu.sv` and the files in `rtl/` are upstream
Menu_MiSTer except for the SNAC work.

Ours: `rtl/snac_psx.v` (a **copy** — see below), its bench, and the wiring in
`menu.sv:243-273`.

**Do not fix upstream code here.** A change to `sys/` or to the upstream parts
of `rtl/` is reverted by the next sync and, worse, is invisible until then. If
something there is genuinely broken, it is broken for every core.

## `rtl/snac_psx.v` is not canonical here

It is copied from `FringeCoder/AmigaCD`, the userspace repo, which owns it —
not from the core, which carries a copy of its own. Fix a bug there and
re-vendor; fixing it here means the two diverge and the next sync quietly
reverts you. CI checks the copy against the sha256 in `rtl/snac_psx.vendor` and
fails if it was edited in place.

```sh
./snac_vendor_check.sh                          # what CI runs
./snac_vendor_check.sh /path/to/amigacd         # also diff the canonical copy
./snac_vendor_check.sh --stamp /path/to/amigacd # re-vendor and restamp
```

Full procedure: `rtl/README.md` in `FringeCoder/AmigaCD`.

## Working here

```sh
bash syntax_check.sh    # parse every synthesisable source, seconds
```

Run it before proposing anything. Nothing else parses `menu.sv` or `rtl/` until
Quartus does, 18 seconds into a fit. It carries one documented exclusion
(`rtl/cos.sv`, an Icarus limitation, not a defect — `docs/state-todo.md` M5) and
prints it on every run, so an exclusion cannot become silent cover. If you need
to add one, give it a reason there.

Benches live in `rtl/sim/<area>/`, compile with `iverilog -g2012`, and print
`RUN: PASS` — CI greps for exactly that. The SNAC bench is parameterised over
clk rate and CI runs it at 28375, 50000 and 100000 kHz, because every timing
constant in the module is an integer division of `CLK_KHZ` and a rate that
truncates badly would only show at that rate. `menu.sv` instantiates it at
100000.

**Falsify a bench before trusting it.** Mutate the DUT so the behaviour is
wrong and confirm the bench fails on the check that names it. A bench that has
never failed has not been shown to test anything. Where checks have not been
falsified, say so — `docs/state-todo.md` M2 is exactly that debt, recorded
rather than glossed.

## Conventions

- Commit subjects are lowercase with a conventional prefix (`feat:`, `fix:`,
  `ci:`, `docs:`). The body explains why, and records what was ruled out.
- Every CI step says why it exists and what it would catch. Keep that up: a step
  whose purpose is not written down is a step someone deletes to get a green
  build.
- `build_id.v` is generated by Quartus and gitignored. `syntax_check.sh` stands
  a stub in when it is absent and removes it again; do not commit one.
- Never commit `.rbf` builds outside `releases/`, and never commit ROMs.
